# تاريخ المشروع

نشأ FactLane من سؤال حول ذاكرة الوكلاء القابلة لإعادة الاستخدام: كيف يمكن لأدوات منفصلة أن تتشارك
حقيقة مفيدة من دون استيراد نصوص محادثات بعضها بعضًا أو سلطتها أو حالة المشروع الحالية؟
وكانت الإجابة التصميمية هي مخزن صغير للحقائق محدد النطاق، مع مصدر موثّق وصلاحية زمنية
وتحقق وسجل صريح لأرقام `revision`.

أنشأت طبقة MCP المحلية الأولى خمس عمليات ذاكرة محددة الحدود ومعالجة دقيقة للنطاق.
ثم أضافت أعمال التخزين اللاحقة آلية compare-and-swap محلية داخل المعاملة لتحديثات متعددة العملاء،
وتغييرات `revision` آمنة عند الأعطال، وإمكانية الاطلاع على الاحتفاظ والسعة. ويمكن ضغط
السجلات المستبدلة المؤهلة من دون عرض السجلات التاريخية باعتبارها حقائق حالية.

يفصل عقد التخزين الحالي بين هوية المساهم وسلطة المتحقق. يمكن للوكيل العادي تقديم
Candidate؛ ويجب على متحقق موثوق ترقيته. ويمكن للبوابة ربط هويات المشروع وسير العمل
والأداة من مضيف موثوق بدلًا من قبول ادعاءات متعارضة داخل الطلب. وتُطبَّق حدود البحث
الدلالي `CURRENT` بعد أهلية التحقق بحيث لا تستطيع Candidates غير المتحقق منها إزاحة
النتائج الحالية.

أدخل المشروع أيضًا مسارًا مخصصًا للمشغّل لاستعادة الذاكرة الحساسة بعد الحوادث،
وفحوص توافق صريحة للواجهة الخلفية SQLite المثبتة، وحدًا أدنى للإصدار المرتبط من SQLite
وهو **3.42.0+**. ولا توسّع هذه الضوابط سطح MCP العام ذي الأدوات الخمس.

أكمل خط الإصدار 0.1.3 أول تأهيل لجاهزية الإنتاج في المشروع لملف النشر المحلي المدعوم.
وشمل ذلك تكافؤ الحزمة/التثبيت، وتوافق النسخ الاحتياطي/الاستعادة الموثوق، والتشغيل المتزامن
المحدود، وسلوك التعطل/إعادة التشغيل، وتكامل مضيف stdio المهيأ، والاسترجاع المشتق من
الإنتاج، والتعامل fail-closed مع سعة SQLite. ويظل الإصدار local-first ويحافظ على عقد
MCP العام ذي الأدوات الخمس عند الإصدار التقني `Revision 2`. وقد حافظ خط 0.1.4 على ذلك العقد وأضاف مسار
embedding-compatibility المؤهل، وأدلة native Windows x64 لوقت التشغيل القياسي، وتقوية
host/bootstrap، وضوابط الإصدار والنشر.

نقل خط 0.1.5 العقد العام إلى الإصدار التقني `Revision 3` والتخزين إلى العقد v3 من دون توسيع سطح MCP ذي الأدوات الخمس. وأضاف `REVOKE`/`REJECT` بصلاحية Owner، وCAS لمجموعات التناقض، وسجلات أحداث/عمليات دورة الحياة، وإعادة فحص يدوية لـ`on_change`، وreadmission منضبطًا، و`OwnerControlService`، وCLI باسم `factlane-owner`، وOwner WebUI المباشرة عبر loopback. كان مشغّل الترحيل/التراجع v2→v3 مسار صيانة مقصورًا على POSIX. لم يُنشر إصدار GitHub المختوم v0.1.5 بنجاح على PyPI بسبب بيانات تبعيات الحزمة؛ وتلاه v0.1.6 بوصفه إصدار الحزمة التصحيحي من دون تغيير عقود المنتج والتخزين تلك.

يوسّع **خط تطوير 0.1.7 الحالي غير المنشور** المنصة المحلية للمستخدم من دون زيادة عدد أدوات MCP العامة. ويضيف دورة حياة Owner Panel المُدارة على Windows x64/AMD64 الأصلي، ومسارات إدارة قاعدة البيانات والإجراءات التدميرية، وترحيل storage-v2→v3 مؤهلًا على Windows الأصلي مع تراجع دقيق إلى ما قبل v3، وتحسينات موثوقية Firefox وHTTPS والجلسات المُدارة. تظل Recovery العامة لحوادث الذاكرة الحساسة عقدًا منفصلًا مقصورًا على POSIX، ولا يضاف ادعاء بدعم Windows ARM64. حزمة Python والموقع العام سطحا نشر منفصلان؛ ورقم المصدر المحلي `0.1.7` ليس بحد ذاته هوية إصدار. راجع [سجل التغييرات](CHANGELOG.md) لملخص التطوير الحالي و[عمليات الإصدار](RELEASE_OPERATIONS.md) لسجلات الإصدار والانتقال الثابتة.

لا يحوّل التأهيل FactLane إلى منصة عامة للاسترجاع أو النشر. تظل جودة اللغة والترتيب
الدلالي خاصة بعبء العمل، ويظل المشغّلون مسؤولين عن إجراءات الاحتفاظ بالنسخ الاحتياطية
والمراقبة والاستعادة الخاصة بكل نشر.

للاطلاع على السلوك الحالي بدلًا من الخط الزمني للمشروع، ابدأ بـ
[README](/)، أو [المعمارية](ARCHITECTURE.md)، أو [البدء السريع](QUICKSTART.md).
