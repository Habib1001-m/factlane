# أدوات MCP الخمس

يتعمد FactLane إبقاء سطح MCP العام صغيرًا:

1. `memory_search`
2. `memory_get`
3. `memory_store`
4. `memory_update`
5. `memory_status`

النقل العام هو stdio يُطلق عبر أمر. أما CLI المحلي للـOwner وOwner WebUI عبر loopback فهما سطحان منفصلان للمشغّل؛ ولا يضيفان أدوات MCP.

مخطط MCP الحي و`factlane --help-tools` هما المرجع المعتمد للحقول الدقيقة وقيم enum والتواقيع.

## `memory_search`

ابحث عن الحقائق المحدودة داخل نطاق دقيق واحد.

تشمل الأبعاد الأساسية:

- النطاق العام الدقيق والهوية المطلوبة؛
- فئة intent من المخطط الحي؛
- دورة حياة الاسترجاع (`CURRENT` أو `REVIEW_HISTORY` الصريح)؛
- نوع البحث (`EXACT` أو `KEYWORD` أو `SEMANTIC` أو `HYBRID` حيث يُسمح به).

لا يقبل استرجاع `CURRENT` إلا سجلات Current المؤهلة. وفي البحث الدلالي، تُطبق الأهلية داخل مسار vector candidates قبل حد نتيجة KNN النهائي، حتى لا تزاحم Candidates الأقرب غير المتحقق منها حقائق Current المؤهلة.

يتبع `CROSS_PROJECT_WORKFLOW` مصفوفة البحث الخاصة به ولا ينفذ fan-out عبر نطاقات المشروعات.

## `memory_get`

اقرأ ذاكرة منطقية واحدة عبر هويتها المنضبطة وافحص منشأها ودورة حياتها ورقم `revision` وحداثتها والبيانات الوصفية المرتبطة بها.

استخدمها عندما تحتاج إلى السجل الدقيق بدل البحث المرتب حسب الصلة.

قد يوجد سجل في التاريخ من دون أن يكون مؤهلًا للاستخدام Current.

## `memory_store`

ساهم بحقيقة محدودة واحدة.

يحتاج طلب التخزين إلى الحقول الدقيقة التي يحددها المخطط الحي، بما في ذلك نوع الذاكرة، ومنشأ المصدر، وسياسة الحداثة، والنطاق، ومفتاح idempotency.

هناك صلاحيتان منفصلتان:

1. **الموافقة على المحتوى** — طلب المستخدم صراحة تذكّر/تخزين الحقيقة، أو وافق صراحة على اقتراح من الوكيل؛
2. **سلطة launcher** — يسمح ملف العملية النشطة بالمساهمة بـCandidate.

يخزن الوكيل المفوض العادي `CANDIDATE`؛ ولا ينشئ `VALIDATED_CURRENT`.

## `memory_update`

نفّذ تحديثًا منضبطًا تحت فحوص دقيقة لرقم `revision` وidempotency.

الأوضاع الأساسية هي:

- `REVERIFY` — أعد التحقق من الذاكرة المنطقية نفسها؛ تستخدم ترقية Candidate قيمة `expected_record_id` الدقيقة؛
- `REPLACE` — أنشئ سجلًا لاحقًا منضبطًا لذاكرة منطقية Current مؤهلة؛ وليس مسارًا لتعديل Candidate؛
- `REVOKE` — disposition مباشر بصلاحية Owner لسجل `VALIDATED_CURRENT` مؤهل؛
- `REJECT` — disposition مباشر بصلاحية Owner لـ`CANDIDATE`.

يتطلب `REVOKE` و`REJECT` أيضًا قيمة `expected_record_id` الحالية الدقيقة، و`observed_group_token` المعروض، ورمز سبب محدودًا ومسموحًا. وهما حالتان منطقيتان لدورة الحياة وليستا محوًا ماديًا.

لا يكتسب وكيل مفوض صلاحية verifier أو Owner لمجرد ظهور `memory_update`.

## `memory_status`

أعد ملاحظات محدودة وللقراءة فقط عن حالة التخزين وملف embedding داخل النطاق.

يمكن لسطح status الإبلاغ عن حالة التوافق/binding، وأعداد حالات دورة الحياة، وملاحظات السعة/الاحتفاظ، وما إذا كانت بصمة runtime الحالية ما تزال تطابق توقعات embedding المخزنة.

لا ينفذ ترحيلًا للتخزين، ولا يعيد embedding للسجلات، ولا يعيد تأهيل runtime متغير بصمت، ولا يشغّل صيانة في الخلفية، ولا يعمل كخدمة مراقبة عامة.

عندما يكون التوافق غير مثبت أو غير مطابق، يحافظ FactLane على مسارات القراءة الآمنة حيث يسمح العقد بذلك ويفشل في وضع مغلق للعمليات الدلالية/المعدلة للـvectors التي تتطلب binding غير المتوافق.

## عمليات Owner منفصلة

تعرض `OwnerControlService` حوكمة محلية موثوقة تتجاوز نموذج التفاعل العادي عبر MCP:

- المخزون وتفاصيل السجل؛
- عروض Candidate وCurrent والتاريخ والتعارضات والصحة والاحتفاظ؛
- revoke/reject؛
- حسم التناقض؛
- reverify/replace موثوقان؛
- إعادة فحص حداثة `on_change` يدويًا؛
- readmission لذاكرة revoked مؤهلة.

استخدم `factlane-owner --help` لمعرفة عقد CLI الحالي.

استخدم `factlane-owner-webui --help` لمعرفة مشغّل واجهة Owner المباشرة عبر loopback. وهو منفصل عن دورة الحياة المُدارة `factlane setup|serve|open|start|stop|status|restart webui`. ولا تمثل أي من واجهتي Owner نقل MCP عبر HTTP.

في مصدر التطوير الحالي، يمكن لـOwner Panel المُدارة أيضًا عرض عمليات قاعدة بيانات بحسب الإمكانات المتاحة، مثل backup artifacts الصريحة، والاستيراد/التصدير، وfull restore، وpermanent purge الخاصة بالمنصة. هذه عمليات Owner/operator وليست أدوات MCP؛ راجع [البدء السريع](QUICKSTART.md) لحدودها الموجهة للمستخدم.

## حالات الفشل المنضبطة

تستخدم حالات الفشل المنضبطة المتوقعة قناة نتيجة MCP العادية مع:

- `status=BLOCKED`؛
- `error_code` ثابت؛
- رسالة آمنة؛
- نتائج فارغة؛
- بيانات وصفية لإعادة المحاولة عند انطباقها.

تفرّع بحسب `error_code`، لا بحسب صياغة الاستثناء.

تظل الاستثناءات الداخلية غير المتوقعة أخطاء نقل بدل إعادة تصنيفها على أنها نتائج FactLane منضبطة.

## مثال: تحقّق من الاتصال قبل الكتابة

طلب status بسيط لمستخدم عام:

```json
{"request":{"scope":"GLOBAL_USER"}}
```

قد يبدو بحث Current بالكلمات المفتاحية ضمن نطاق مشروع كما يلي:

```json
{
  "request": {
    "scope": "PROJECT",
    "project_id": "example-project",
    "intent_class": "CURRENT_PROJECT_STATE",
    "query": "What release constraints are recorded?",
    "retrieval_mode": "CURRENT",
    "retrieval_mode_kind": "KEYWORD"
  }
}
```

عندما تكون بيئة استضافة موثوقة قد ربطت بالفعل هوية المشروع/سير العمل/الأداة المناسبة، اتبع المخطط الحي واحذف الهوية المتعارضة التي يرسلها المستدعي.
